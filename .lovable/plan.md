# تشغيل النظام على استضافة Hostinger

## الخلاصة أولاً

الاستضافة المشتركة في Hostinger (Web Hosting / Premium / Business) **لا تستطيع تشغيل هذا النظام**، والسبب تقني بحت:

| ما يحتاجه النظام | الاستضافة المشتركة |
|---|---|
| تشغيل خادم Node.js دائم | غير متاح (PHP فقط) |
| قاعدة بيانات PostgreSQL | غير متاح (MySQL فقط) |
| خدمة المصادقة والتخزين (عمليات خلفية) | غير متاح |
| صلاحيات root / Docker | غير متاح |
| فتح منافذ مخصصة | غير متاح |

لا توجد طريقة التفاف حول هذا — النظام مبني على Node.js وPostgreSQL، والاستضافة المشتركة تشغّل PHP وMySQL فقط.

## الحل: ترقية إلى Hostinger VPS

Hostinger توفّر VPS من نفس الحساب، وهو يشغّل النظام كاملاً (التطبيق + قاعدة البيانات + المصادقة + التخزين) على سيرفر واحد.

- الخطة المناسبة: **KVM 2** (2 vCPU / 8GB RAM / 100GB SSD) — كافية لـ 31 موظفاً مع هامش نمو
- الحد الأدنى المقبول: KVM 1 (1 vCPU / 4GB)
- نظام التشغيل عند الإنشاء: **Ubuntu 24.04 with Docker** (متاح جاهزاً في لوحة Hostinger)

## ما سأضيفه للمشروع

ملف دليل عربي مفصّل `deploy/HOSTINGER.md` يغطي خطوة بخطوة:

1. **إنشاء VPS** من لوحة hPanel واختيار قالب Ubuntu + Docker وضبط كلمة مرور root
2. **الدخول عبر SSH** (من متصفح Hostinger أو من الجهاز) وتحديث النظام
3. **تأمين السيرفر**: مستخدم غير root، مفتاح SSH، جدار حماية UFW يفتح 22/80/443 فقط، وتفعيل Fail2ban
4. **رفع المشروع** وتشغيل حزمة `deploy/` الجاهزة (قاعدة البيانات + المصادقة + REST + التخزين + التطبيق)
5. **ربط الدومين**: توجيه سجل A من إدارة الدومين في Hostinger إلى IP السيرفر، مع شرح للحالتين (دومين مستقل أو نطاق فرعي مثل `hr.yateemdev.org`)
6. **شهادة HTTPS مجانية تلقائية** عبر Caddy كوسيط أمامي — تجديد تلقائي بلا تدخل
7. **البريد الإلكتروني**: استخدام SMTP الخاص بـ Hostinger لإشعارات النظام
8. **النسخ الاحتياطي**: مهمة cron يومية لقاعدة البيانات وملفات الوثائق + نسخ Hostinger snapshots
9. **المتابعة والصيانة**: مراجعة السجلات، إعادة التشغيل التلقائي، تحديث النظام عند إصدار نسخة جديدة
10. **جدول حل المشاكل الشائعة**: المنفذ مشغول، الدومين لا يفتح، فشل الشهادة، نفاد الذاكرة

## تعديلات تقنية مرافقة

- إضافة خدمة `caddy` إلى `deploy/docker-compose.yml` (تعمل عند تفعيل ملف `docker-compose.https.yml` الإضافي) لتوفير HTTPS ودومين واحد يخدم التطبيق وبوابة الخدمات معاً على `443`
- إضافة `deploy/Caddyfile` يوجّه `/auth/v1` و`/rest/v1` و`/storage/v1` إلى البوابة وباقي المسارات إلى التطبيق — بهذا يصبح كل شيء خلف دومين واحد بدل منفذين
- إضافة `deploy/backup.sh` لنسخة احتياطية يومية مضغوطة مع حذف النسخ الأقدم من 30 يوماً
- تحديث `deploy/README.md` بإشارة إلى دليل Hostinger

لن يتغير أي شيء في كود التطبيق نفسه — الإضافات كلها داخل مجلد `deploy/`.

## البديل إن تعذّرت الترقية

إبقاء التطبيق على الاستضافة الحالية (Lovable) والاكتفاء بربط دومين Hostinger الخاص بكم عليه: تُضاف سجلات DNS من لوحة Hostinger ويعمل النظام على `hr.yateemdev.org` مباشرة، بدون سيرفر ولا صيانة. الفرق أن قاعدة البيانات تبقى في السحابة لا داخل السيرفر الخاص.
