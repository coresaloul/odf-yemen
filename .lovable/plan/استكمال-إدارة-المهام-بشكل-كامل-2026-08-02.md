# استكمال إدارة المهام بشكل كامل

الصفحة الحالية تكتفي بإنشاء مهمة (يدوياً أو صوتياً)، فلتر بالحالة، وأزرار تقدم ثابتة (25/50/75/100). لا يوجد تعديل، حذف، بحث، تفاصيل، مرفقات نقاش، أو مهام فرعية. الخطة تكمل الوحدة بالكامل.

## 1. عرض وتصفية متقدمة

- شريط بحث نصي (العنوان/الوصف).
- فلاتر: الحالة، الأولوية، الموظف المكلّف، الإدارة/القسم، نطاق تاريخ الاستحقاق، «المتأخرة فقط».
- تبويبات سريعة: مهامي / المهام التي كلّفت بها / كل المهام (حسب الصلاحية).
- ترتيب: الأحدث، الاستحقاق الأقرب، الأولوية.
- عرضين: قائمة بطاقات (الحالي) + لوحة كانبان بأعمدة الحالات مع السحب لتغيير الحالة.
- مؤشرات لونية للمهام المتأخرة (تاريخ الاستحقاق مضى والحالة غير مكتملة).
- بطاقات إحصائية أعلى الصفحة: إجمالي، قيد التنفيذ، مكتملة، متأخرة، متوسط الإنجاز.

## 2. دورة حياة المهمة الكاملة

- تعديل المهمة (كل الحقول) للمدير التنفيذي/المدير المباشر أو منشئ المهمة.
- حذف المهمة مع تأكيد.
- تغيير الحالة يدوياً: جديدة / قيد التنفيذ / مكتملة / ملغاة، مع ربط منطقي بنسبة الإنجاز.
- إعادة تعيين المهمة لموظف آخر (يُطلق إشعار التكليف تلقائياً).
- تحديد نسبة إنجاز حرة بمنزلق (0–100) بدل الأزرار الثابتة فقط.
- الموظف يستطيع تحديث تقدم مهامه فقط وإضافة ملاحظة تنفيذ.

## 3. صفحة/نافذة تفاصيل المهمة

نافذة بتبويبات:
- **التفاصيل**: كل الحقول + المكلِّف/المكلَّف + الأولوية + الوزن + التواريخ + مصدر الإنشاء (صوتي/يدوي).
- **سجل المتابعة**: قائمة `task_updates` (ملاحظة + نسبة + من + متى) مع نموذج إضافة تحديث/تعليق.
- **المهام الفرعية**: قائمة تحقّق (checklist) بعناصر قابلة للإضافة والشطب، ونسبة الإنجاز التلقائية منها.
- **المرفقات**: رفع ملفات مرتبطة بالمهمة (تخزين في مساحة الملفات الخاصة بالنظام).

## 4. تحسينات إنشاء المهمة

- التحقق من الحقول (عنوان مطلوب، تاريخ استحقاق ≥ تاريخ البدء).
- حقل تاريخ البدء (موجود في القاعدة وغير ظاهر في النموذج).
- إنشاء مهمة لعدة موظفين دفعة واحدة (نسخة لكل موظف).
- مهام متكررة اختيارية (يومي/أسبوعي/شهري) تُولّد النسخة التالية عند الإكمال.
- قوالب مهام سريعة.

## 5. الإشعارات والتقارير

- الحفاظ على الإشعارات الحالية (تكليف/تغيير حالة) وإضافة إشعار قرب الاستحقاق والتأخر.
- إضافة تصدير قائمة المهام المعروضة (بعد الفلترة) إلى Word/PDF بنفس آلية التقارير الحالية.

## التفاصيل التقنية

- **قاعدة البيانات (هجرة واحدة)**:
  - `task_subtasks` (task_id, title, is_done, position) + GRANT + RLS بنفس منطق سياسات `tasks`.
  - `task_attachments` (task_id, file_path, file_name, uploaded_by) + bucket خاص `task-files` مع سياسات وصول.
  - أعمدة على `tasks`: `recurrence` (نص/enum اختياري)، `parent_task_id` للمهام المتكررة المتولدة.
  - إضافة قيمة `overdue` غير مطلوبة — تُحتسب المتأخرة منطقياً من `due_date` + الحالة.
- **الواجهة**:

  - إبقاء الاستعلامات عبر عميل Supabase في المتصفح مع `useQuery` ومفتاح `["tasks-page"]`، وإضافة استعلام تفاصيل منفصل لكل مهمة.
  - صلاحيات العرض في الواجهة تعتمد `useAuth()` (`isManager`, `employee.id`) مع بقاء الحماية الفعلية في سياسات RLS.
