# تشغيل النظام على جهاز Windows داخل المؤسسة

الخيار المطلوب الآن: تحويل جهاز يعمل بنظام Windows إلى سيرفر يشغّل النظام كاملاً (التطبيق + قاعدة البيانات + المصادقة + التخزين)، ويستخدمه الموظفون من أجهزتهم عبر الشبكة الداخلية.

هذا ممكن بالكامل، وحزمة `deploy/` الموجودة في المشروع تعمل على Windows كما هي عبر Docker Desktop.

## المتطلبات

- Windows 10 (إصدار 2004 فأحدث) أو Windows 11 أو Windows Server 2019/2022
- معالج يدعم المحاكاة الافتراضية (Virtualization) مفعّلة من BIOS
- ذاكرة 8GB فأكثر، ومساحة فارغة 40GB فأكثر
- الجهاز يبقى مشغّلاً طوال ساعات العمل، ويُفضّل توصيله بالشبكة عبر كابل مع **عنوان IP ثابت**

## ما سأضيفه للمشروع

### 1) دليل عربي مفصّل `deploy/WINDOWS.md`

يغطي خطوة بخطوة مع أوامر جاهزة للنسخ:

1. **تفعيل WSL2** (`wsl --install`) وإعادة التشغيل
2. **تثبيت Docker Desktop** وضبطه على WSL2 backend وتفعيل «التشغيل مع بدء Windows»
3. **تثبيت Git** ونسخ المشروع إلى `C:\odf-hr`
4. **تعبئة ملف الإعدادات** `.env` وتوليد المفاتيح داخل Docker (بدون الحاجة لأدوات Linux على Windows)
5. **الإقلاع** بأمر واحد، ثم تطبيق بنية قاعدة البيانات، ثم إنشاء حساب المدير التنفيذي
6. **تثبيت IP الجهاز** من إعدادات الشبكة أو حجزه من الراوتر (DHCP Reservation)
7. **فتح المنافذ في جدار حماية Windows** (80 و3000 و8000) للشبكة الداخلية فقط
8. **الدخول من أجهزة الموظفين**: `http://192.168.1.x` من أي متصفح على نفس الشبكة
9. **التشغيل التلقائي** عند إقلاع الجهاز وبعد انقطاع الكهرباء
10. **النسخ الاحتياطي اليومي** وجدولته عبر Task Scheduler
11. **الإيقاف والتحديث والصيانة**
12. **جدول حل المشاكل الشائعة**: WSL لا يعمل، Docker لا يقلع، الجهاز لا يُفتح من الشبكة، نفاد الذاكرة، تعارض المنافذ

### 2) ملفات تشغيل جاهزة لـ Windows

- `deploy/windows/start.bat` — تشغيل النظام كاملاً بنقرة واحدة
- `deploy/windows/stop.bat` — إيقاف آمن
- `deploy/windows/setup.ps1` — تهيئة أول مرة: توليد كلمات المرور والمفاتيح تلقائياً وكتابة `.env`، ثم الإقلاع، ثم تطبيق ملفات قاعدة البيانات، ثم إنشاء حساب المدير
- `deploy/windows/backup.ps1` — نسخة احتياطية مضغوطة لقاعدة البيانات وملفات الوثائق مع حذف ما يتجاوز 30 يوماً
- `deploy/windows/firewall.ps1` — فتح المنافذ للشبكة الداخلية فقط بأمر واحد

بهذا لا يحتاج المسؤول لكتابة أوامر Linux إطلاقاً.

### 3) تشغيل تلقائي وثبات

- إضافة سياسة `restart: unless-stopped` (موجودة أصلاً) + تفعيل إقلاع Docker Desktop مع Windows = عودة النظام تلقائياً بعد أي إعادة تشغيل
- إضافة مهمة Task Scheduler اختيارية تتحقق كل 10 دقائق أن الخدمات تعمل وتعيد تشغيلها عند الحاجة
- توجيه المنفذ 80 إلى التطبيق حتى يكتب الموظف العنوان بدون رقم منفذ

### 4) الوصول من خارج المكتب (اختياري)

شرح مختصر لخيارين آمنين:
- **VPN** للمؤسسة (الأفضل أمنياً)
- **Cloudflare Tunnel** مجاني: يربط الجهاز بدومين `hr.yateemdev.org` مع HTTPS دون فتح أي منفذ على الراوتر

## مقارنة سريعة بين الخيارات

| | جهاز Windows داخل المكتب | Hostinger VPS |
|---|---|---|
| التكلفة | لا شيء إضافي | اشتراك شهري |
| السرعة داخل المكتب | ممتازة (شبكة محلية) | تعتمد على الإنترنت |
| العمل عند انقطاع الإنترنت | يعمل | لا يعمل |
| العمل عند انقطاع الكهرباء | يتوقف (يحتاج UPS) | يعمل |
| الوصول من خارج المكتب | يحتاج VPN أو Cloudflare Tunnel | متاح مباشرة |
| الصيانة | على فريقكم | جزئياً على المزوّد |

**التوصية**: البدء بجهاز Windows داخل المكتب مع UPS ونسخ احتياطي يومي على جهاز/قرص آخر. وإن احتيج لاحقاً وصول خارجي دائم، يُضاف Cloudflare Tunnel أو يُنقل النظام إلى VPS — نفس الملفات تعمل في الحالتين دون تغيير في الكود.

## ملاحظات

- لا تغيير على كود التطبيق؛ كل الإضافات داخل مجلد `deploy/`.
- الاستضافة المشتركة في Hostinger تبقى غير قادرة على تشغيل النظام (PHP وMySQL فقط، بينما النظام يحتاج Node.js وPostgreSQL).
- ميزة «إضافة مهمة بالصوت» تحتاج اتصال إنترنت ومفتاح خدمة ذكاء اصطناعي؛ باقي النظام يعمل بلا إنترنت.
